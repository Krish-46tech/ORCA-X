# ORCA-X

ORCA-X is a marine research workflow prototype that makes data provenance visible. The current complete vertical slice returns the ten stage specifications alongside a deterministic calculation over **synthetic demonstration SST values**. It does not present those values as observations, and it does not yet call an LLM or fetch NOAA data.

## Features

- React + TypeScript research workspace with responsive dark ocean UI and calculated chart.
- FastAPI backend, typed request validation, health/config, research, history, prompt, evaluation, upload, and demo endpoints.
- Python annual summary and linear least-squares trend calculation.
- Ten distinct, versioned prompt definitions exposed through the Prompt API: Orchestrator, Query Decomposition, Marine Research Planner, Data Retrieval, Data Quality, Scientific Analysis, Evidence Verification, Critic, Scientific Synthesis, and Final Report.
- Demo report clearly distinguishes generated example data from real evidence. JSON report export and CSV/JSON validation preview.
- Docker Compose setup and backend smoke tests.

## Architecture

The browser posts a validated research request to FastAPI. The backend calculates descriptive statistics in Python, builds a provenance-aware report, and returns the chart series. The ten agent entries are defined prompt specifications; they are not executed as autonomous agent calls. Demo series are generated by a deterministic function; they are not measurements. Prompt records are returned separately by `/api/prompts`. An OpenAI key may be configured for future integration, but the current prototype does not send it or use an AI model.

## Ten prompts

Each prompt has an ID, name, version, role, objective, input/output schema description, instructions, and error behavior. Each specification is stored as a separate JSON file in `backend/app/prompts/`; these are prompt specifications, not claims that ten independent LLM calls have executed.

## Run locally

Requires Python 3.11+ and Node 20+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
uvicorn app.main:app --app-dir backend --reload
```

In another terminal:

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173. API docs: http://localhost:8000/docs.

## Environment

Copy `.env.example` to `.env` if desired. `OPENAI_API_KEY` and `OPENAI_MODEL` are placeholders for the future AI integration and currently do not enable model execution. Do not commit secrets. `CORS_ORIGINS` controls allowed browser origins.

## Docker

```bash
docker compose up --build
```

Open http://localhost:8080. Nginx proxies `/api` requests to the backend container, so the connected UI works in Compose.

## Data and limitations

NOAA ERDDAP is identified as a candidate public source but live retrieval is **not implemented or verified**. Data upload validates and previews CSV/JSON (max 5 MB) but does not yet use uploaded rows in analysis. Sessions are in-memory and disappear when the process restarts. History, delete, rerun, and polling endpoints work for current process sessions. API key config is status-only. Prompt Lab/Evaluations/Settings navigation is scaffolded; prompts/evaluations have API endpoints, but those pages are not yet implemented. Rate limiting, persistent database, streamed execution, real agent recovery loop, authentication, and deployment proxy remain future work. Do not use results for scientific conclusions.

## Tests

```bash
cd backend
pytest -q
```

The tests cover health, prompt count, validation, synthetic provenance, calculation, and unknown sessions.

## Deployment

The root `Dockerfile` builds the Vite dashboard and packages it with FastAPI, which serves the UI and `/api` routes from one service. `render.yaml` is a Render Blueprint with a `/api/health` check and Singapore region. Push the repository to GitHub, then in Render choose **New → Blueprint**, connect that repository, and apply the `render.yaml` service. Render will provide an `onrender.com` URL after its first successful deployment. The free instance may sleep when idle. No public deployment has been performed from this workspace. Before using this as a scientific service, implement persistence, rate limiting, and actual retrieval/model execution.
